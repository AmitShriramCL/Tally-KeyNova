What Problem Are We Solving?
Why this integration exists
❌ Without Integration

Every day, the property accountant opens TallyPrime and manually types in every room charge, every payment received, every POS bill — one by one. For a 50-room hotel with 100+ daily transactions, this takes 2–3 hours of manual work. Mistakes happen. Data is always a day behind.

✅ With Integration

The accountant opens the KeyNova Tally Interface, selects yesterday's date, clicks Fetch, selects all transactions, and clicks Export. Tally is updated in under a minute. No typing, no mistakes, real-time accuracy.

Simple analogy

Think of KeyNova PMS as the hotel's operations register — it records every room sold, every meal ordered, every payment received. Tally is the hotel's accounting ledger — where the finance team does their work. Without integration, someone has to physically copy every entry from the operations register into the accounting ledger. Our integration automates that copy — accountant just reviews and approves.

Important: This is NOT a fully automatic integration. The accountant manually triggers the export whenever they want — daily, weekly, or any schedule they prefer. They are always in control of what goes into Tally.

localhost:9988 on hotel PC

Why is the KTC connector needed? The browser has a security rule — it won't show your code a server's response unless that server explicitly says "yes, you're allowed to read this." Tally (old software) doesn't say this. KTC is a tiny middleman that sits between the browser and Tally, forwards the request, and adds that permission stamp to Tally's response before giving it back to the browser. That's literally all it does.

Authentication and data access

What happens behind the scenes

1
Accountant enters credentials on KTI

Same username and password as KeyNova PMS.

2
KTI calls KeyNova PMS login API

KTI sends the credentials to KeyNova's server. KeyNova verifies them and returns a session token.

3
KTI stores the token in the browser

From this point, every time KTI fetches transaction data, it uses this token to prove it's authorised.

✓
Accountant is logged in — KTI dashboard opens

All their property's transaction data is now accessible to KTI via the KeyNova API.

One login, two apps: The accountant uses the same KeyNova credentials on both apps. From KeyNova's perspective, KTI is just another client application calling its API — exactly like how a mobile app and a web app can both be logged into the same account.

The One-Time Setup Journey
Done once per property — takes about 30–60 minutes
Prerequisites before starting setup: The accountant must have already created all the required ledger accounts in TallyPrime (Room Rent, GST accounts, City Ledger accounts for OTAs, Payment type accounts etc.). KTI cannot create Tally ledgers — it only posts data to ledgers that already exist.
1
Step 1 — Connect to Tally
Accountant does this

Enter the Tally company name (must match exactly as it appears in TallyPrime), the Tally server address, and port. For a local PC, the address is localhost and port is 9000.

Company name must be exact. If TallyPrime shows "Hotel Grand Palace Pvt. Ltd" — that exact text, same capitalisation, same spacing — is what you enter. A single character difference means Tally will reject every post.
2
Step 2 — Install the KTC Connector
Hotel IT does this

KTI shows a download button for the KeyNova Tally Connector installer. Download and run it on the same Windows PC where TallyPrime is installed. It installs as a background Windows service — starts automatically on every reboot. After installation, KTI shows a green Connector Online badge confirming it's working.

3
Step 3 — Choose Recording Mode & Settings
Accountant decides

Choose how room revenue should be recorded in Tally. Three options:

  • Day-wise (recommended): Each night's room charge is posted as a separate entry on that exact date.
  • Checkout-wise: All nights of a stay are posted together on the checkout date.
  • Summarized: Everything for a stay is merged into one single entry.

Also set the Place of Supply (state) — this determines whether GST is split as CGST + SGST (same state) or IGST (different state).

4
Step 4 — Configure Voucher Types
Accountant does this

Properties often create custom voucher registers in TallyPrime per financial year — like "FD Sales 24-25" instead of just "Sales". This step maps each KeyNova transaction type to the exact Tally voucher type name the accountant has set up.

5
Step 5 — Ledger Mapping (most important step)
Accountant does this

This is covered in detail in the next section. Every item from KeyNova (payment method, tax type, extra charge, booking source) is mapped to its corresponding ledger name in Tally. This is a one-time table that the accountant fills in once and rarely changes.

🗂️
How Ledger Mapping Works
The most important configuration step

KeyNova and Tally use different names for the same concepts. Ledger mapping is the dictionary that tells KTI: "when you see this from KeyNova, use this ledger name in Tally." This is done once and stays saved.

Simple analogy

Imagine KeyNova calls a payment method "Card" but the accountant created a ledger in Tally called "Credit Card Receipts". Without mapping, KTI wouldn't know they're the same thing. The mapping table is just: KeyNova name → Tally ledger name. One line per entity.

How KTI auto-populates the mapping table

Instead of asking the accountant to type everything from scratch, KTI automatically fetches all the entities the property has configured in KeyNova PMS — all their payment methods, extra charge types, tax codes, booking sources, POS categories — and lists them. The accountant only needs to fill in the right-hand column: the matching Tally ledger name.

The #1 rule: The Tally ledger name the accountant types here must match EXACTLY what exists in TallyPrime — same spelling, same capitalisation, same spacing. If it doesn't match, Tally will create a new wrong ledger instead of posting to the right one. Always verify against TallyPrime's ledger list.

What happens when a new payment method is added later?

If the hotel adds a new payment method in KeyNova PMS (e.g. "Cheque"), that new entity will appear on the mapping table the next time the accountant visits. They just add the Tally ledger name for it and save. Everything already mapped continues to work unchanged.

Daily Use — The Accountant's Workflow
After setup is done — what happens every day

Once setup is complete, the accountant's daily routine with KTI is simple. The whole process for a busy hotel takes under 5 minutes.

1
Open KTI and log in

Open tally.keynova.com in the browser on the Tally PC. Log in with KeyNova credentials. Takes 10 seconds.

2
Go to a transaction type

Click on Sales, or Receipts, or Payments, or Journal — whichever they want to post today.

3
Select date range and click Fetch

Enter yesterday's date (or any date range). Click Fetch. KTI calls KeyNova API and shows all transactions for that period.

4
Select All → Export to Tally

Click the Select All checkbox. Click Export to Tally. KTI builds the XML vouchers and sends them to Tally through the KTC connector.

✓
See results — repeat for other types

Each row shows Posted Successfully or an error. Then repeat for Receipts, Payments, Journals.

What happens if a row shows an error?

Common error: "Ledger not found"

Tally couldn't find the ledger name KTI sent. Usually means a typo in the Account Mapping. The accountant fixes the ledger name in KTI's mapping settings and re-exports that row.

Common error: "Connector offline"

The KTC connector service on the hotel's PC has stopped running (PC was restarted and service didn't start). The accountant restarts the KTC Windows service and tries again.

End-to-End Example
Hotel Grand Palace — from onboarding to first Tally export

Let's follow Hotel Grand Palace — a 50-room hotel in Gujarat — from the moment they sign up on KeyNova to the moment their first transactions appear in TallyPrime.

Phase 1
🏨 Hotel Grand Palace signs up on KeyNova PMS

The hotel manager creates an account on KeyNova PMS and sets up their property:

  • Property name: Hotel Grand Palace, location: Surat, Gujarat
  • Rooms configured: 50 rooms across three types — Standard, Deluxe, Suite
  • Rate plans set: Best Available Rate, OTA Rate, Corporate Rate
  • Extra charges defined: Extra Bed (₹1,000/night), Mini Bar (per consumption), Laundry
  • Payment methods enabled: Cash, Card, UPI, Bank Transfer
  • Booking sources added: Walk-in, Booking.com, MakeMyTrip, Corporate ABC Ltd
  • Restaurant outlet set up: The Grand Dining — Food and Beverage categories
  • GST configured: 12% for Standard/Deluxe rooms, 18% for Suites, 5% for restaurant

The hotel is now live on KeyNova. Guests are being checked in. Transactions are flowing in.

Phase 2
🧮 Mr. Ramesh (accountant) sets up Tally

Before touching KTI, Mr. Ramesh does his preparation work in TallyPrime on the hotel's PC:

  • Creates company: "Hotel Grand Palace Pvt. Ltd" (2024-25 financial year)
  • Creates income ledgers: Room Rent Standard, Room Rent Deluxe, Room Rent Suite
  • Creates extra charge ledgers: Extra Bed Charge, Mini Bar Revenue, Laundry Revenue
  • Creates GST ledgers: CGST Output @6%, SGST Output @6%, CGST Output @9%, SGST Output @9%
  • Creates payment ledgers: Cash, Credit Card Receipts, UPI Receipts, Bank Transfer
  • Creates city ledger accounts (Sundry Debtors): Booking.com, MakeMyTrip, ABC Corporate
  • Creates advance ledger: Advance from Guests
  • Creates custom voucher types: FD Sales 24-25, FD Receipt 24-25, FD Journal 24-25

All ledgers exist in Tally. Ready to connect.

Phase 3
⚙️ KTI one-time setup — 45 minutes

Mr. Ramesh opens tally.keynova.com, logs in with his KeyNova credentials, and does the one-time setup:

  • Step 1 — Connect Tally: Enters company name "Hotel Grand Palace Pvt. Ltd", server: localhost, port: 9000
  • Step 2 — Install KTC: Downloads and installs the connector on the Tally PC. KTI shows green "Connector Online" badge.
  • Step 3 — General settings: Chooses Day-wise recording, Place of Supply: Gujarat
  • Step 4 — Voucher types: Maps Sales → "FD Sales 24-25", Receipts → "FD Receipt 24-25", Journal → "FD Journal 24-25"
  • Step 5 — Ledger mapping: KTI auto-loads all entities from KeyNova. Mr. Ramesh fills in the Tally ledger names for each one (shown in the mapping table above)

Setup complete. KTI is ready to post transactions.

Phase 4
🛎️ The first guest — Yogasen Naidoo stays 3 nights

Yogasen Naidoo books via Booking.com for 3 nights (1–3 April) in a Deluxe room at ₹2,500/night. He pays ₹1,000 advance before arrival, ₹2,000 cash on night 1, ₹3,000 by card on checkout. Booking.com owes the hotel the remaining ₹3,000. A discount of ₹1,500 was given.

All of this is recorded in KeyNova PMS by the front desk. Now it needs to go to Tally.

Phase 5
📊 4th April — Mr. Ramesh exports to Tally

Mr. Ramesh opens KTI the next morning. He goes through each transaction type and exports them all:

  • Sales tab: Fetches 1–3 April. Sees 3 rows — one for each night's room charge. Clicks Export. All three post successfully as "FD Sales 24-25" vouchers in Tally.
  • Receipts tab — Advance Deposit: Fetches 31 March. Sees the ₹1,000 advance. Exports it. Tally records: Bank Transfer received → Advance from Guests.
  • Receipts tab — Received From Guest: Fetches 1–3 April. Sees ₹2,000 cash and ₹3,000 card. Exports both. Tally records them as receipt entries.
  • Journal tab: Fetches 1 April. Sees the advance transfer entry (advance applied on checkin). Exports it.
  • Receipts tab — City Ledger: Booking.com's ₹3,000 settlement will appear here when Booking.com actually pays — exported then.

All rows show Posted Successfully. Mr. Ramesh opens TallyPrime, checks the FD Sales 24-25 voucher register — all three nights of Yogasen Naidoo's stay appear correctly with the right ledger entries and GST breakdown.

Total time: under 5 minutes. Zero manual data entry. Zero errors.

What appears in TallyPrime's voucher register: The accountant can open TallyPrime → Display → Account Books → Sales Register → select "FD Sales 24-25" and see all room sale vouchers posted from KTI, with correct dates, guest names in narration, GST split into the right ledgers, and balanced debit/credit entries. The P&L and GST reports update automatically.
